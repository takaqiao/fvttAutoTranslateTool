# 手动投骰接入范围 · 2026-09-30

用户要求：保留前后自动化，将插件代投的真实随机骰改为操作者在原生窗口确认。按“其他不变”保留原操作者、目标、费用、权限、秘骰、来源凭据及防重复结算；普通原生快捷操作不全局拦截。不增加移动、距离、视线或接触确认。

## 接入与保留

| 入口 | 本次接入 | 保留的行为 |
|---|---|---|
| 自动攻击、反应攻击、组合武器与法术 | 原生检定与伤害窗口；兼容用户关闭快捷窗口的偏好 | 原操作者、MAP、来源、首攻击取消不预付、已投部分与已付法术保留 |
| 豁免、恐惧、医疗、休息等检定 | 原生 Statistic/Check 确认 | 原 DC、成功度、目标与后续效果 |
| 付费重掷 | 原生第二次检定窗口 | 原费用与 uncertain 契约；取消或失败时保存 GM 原骰参考，不作为最终结果自动结算 |
| 原本直接 evaluate 的伤害/治疗骰 | PF2e 原生 DamageModifierDialog，捕获实际确认结果后续接 | 完整内部公式、原来源、可见范围、一次发布与一次应用 |
| Workbench 回忆知识 | 唯一实际检定手动确认 | 多技能共享已保留骰点，锁定目标匹配技能，秘骰与修正预览不增加骰子 |
| 原生不显示修正窗口的平检 | Foundry 原生“投骰／取消”确认框 | 保留 flat-check 类型与 DC，不引入技能修正 |

驾轻就熟固定 10、技能元数据探测、已保留骰的 fromTerms/alter/合并均不产生新随机骰，不增加额外确认。普通外部模组自己发起的快捷骰不在本插件代投范围。

## 等待与取消

人类窗口等待不计入 RPC 超时。持久完成记录与准确原生卡 ID 可接回丢失回复；准确文档同步、真实伤害应用仍保留原期限。断线、GM 交接或原身份改变不能授权重投。窗口在异步准备后晚到时，保留该次精确标记的拦截到原调用结束并关闭旧窗口。

Workbench 医疗的动画续接限于本次宏。确认后的治疗卡自行展示 DSN；无治疗量分支仅采纳本次真实检定动画完成，忽略无关骰。取消会清理本次监听，不伪造全局事件。
