# `english-baseline/` —— 英文基准总索引

> **这份索引存在的唯一理由**：这些目录**光看名字分不清各自是什么**，
> 而挑错一份就会算出错的跟版差量。2026-08-17 补写。
> 各目录内部还有更细的 README（`crucible-0.10.2/` · 两份 `*-preupgrade-2026-08-15/` ·
> `crucible-cn-0.9.0-shipped-en/` 等），本文件只回答「该拿哪一份」。

## 三类目录，读名字要会区分

| 命名形态 | 是什么 | 谁产的 |
|---|---|---|
| `<包>-<上游版本>/`<br>（`crucible-0.10.2` · `crucible-0.10.1` · `ember-0.6.0`） | **上游英文的原始抽取** | `3-常用脚本/extract/extract_en.mjs` |
| `<包>-<版本>-preupgrade-<日期>/` | **升级前快照**，从当时的 `compendium/en` 原样截下 | `3-常用脚本/qa/capture_baseline.py` |
| `<包>-cn-<发版号>-shipped-en/` | **某次汉化发版当时随包发出去的英文**，用来答「从那次发版到今天英文改了什么」 | 从插件仓 git tag 截 |

## 两条一定要记住的规矩

1. **跟版差量必须按「增 / 删 / 改」三个桶枚举。** 只数「增」和「删」必漏第三桶。
   0.10.2 那一轮就整桶漏了「改」的 10 叶。
2. **「改前」的英文只能从本目录取，绝不能从已经升级的上游现抽。**
   上一轮漏掉第三桶的根因正是拿升级**之后**的上游当基线 —— 基线被污染，
   于是本该处理的改写被当成了「全库既有噪声」。

两份 `*-preupgrade-2026-08-15/` —— 对应的上游/发版状态**已经不在磁盘上了，重抽只会拿到今天的英文**。
