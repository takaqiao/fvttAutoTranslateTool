# PF2e 第三方自动化补全 0.9.14

本版减少移动、角色维护和聊天渲染中的重复扫描。

## 待发布：补全伤害卡的 Toolbelt 目标

- 双重打击、法术组合／法术横扫、战役能力追加伤害、熊支援和高电压生成最终伤害卡时，写入该次已确认的 Token 目标。执行 GM 当时 T 了自己或别人，也不会再让 Toolbelt 用它重建这些卡的名单。
- 现有战役能力原生伤害钩子核对动作、命中卡、武器、施用者和目标后，同步目标字段；保留 Toolbelt 的豁免、溅射、已应用和合并数据。没有新增监听器、移动监控或后台轮询。
- 本地完整回归 1,523 项通过，0 失败、0 跳过；实际 Toolbelt 3.56.2 初始化函数的隔离验证覆盖两个钩子顺序。尚未发布或进行玩家多客户端实测。爱达梦模板定靶时机、医师探访的操作端与移动流程仍是后续改造，未包含在本补丁中。

## 0.9.14：按需维护与聊天查询

- Token 纯移动使用 Foundry 自带的效果分类缓存，只检查涉及该 Token 的忠诚卫士关系；旧数据修复、时间到期、盾牌与角色链接变更仍保留完整维护。GM 交接时清除无法继续证明的上一个动作记录。
- 指定角色的旧数据维护只为该队员生成修复计划，不再为每个队员重复序列化整队；仍检查当前主 GM、成员身份和停用标记。
- 轰然喝彩原卡按消息 UUID 查询相关角色。索引随 Actor、基础角色依赖的未链接 Token、场景和链接变化刷新；每次展示仍读取当前记录，保留重复来源、已结束来源和人工核对提示。该索引不参与豁免、反应或维持的授权。
- Workbench 未启用、版本不受支持或缺少所需接口时跳过脚本下载；下载及正文读取超过 10 秒时结束等待。动作路由在首个匹配后停止查询其余 provider。
- 隔离计数对照：48 角色、1,200 件普通物品、3 次无关移动，物品规则读取由 3,600 次降为 0；5 人逐个维护时角色序列化由 25 次降为 5。不是正式世界 FPS 或卡顿时间测量。
- 回归验证：1,507 项通过，0 失败、0 跳过，包含本机 PF2e 8.5.1、Foundry 14.368 和对应宏的原生源码用例。

## 0.9.13：未支持来源的伤害结算

- 激进手术的内嵌伤害或宏伤害等无法验证为自动反应来源时，保留原生伤害结算，不再因为受伤者位于冠军灵光内就抛错。此时不发起反应选择、不支付资源、不附加抗力或衰弱；提示本次没有自动触发救赎瞥视。
- 来源校验继续决定能否自动使用救赎瞥视。已经等待选择、付款、进入原生或留下已处理／不确定记录的同次伤害仍阻止重复执行，不能通过修改原卡绕过。
- 进入反应流程后的来源复核、忏悔／抗拒、付款和回执规则保持原样；提示消息自身发生异常也不会阻止普通伤害。
- 不包含 Sequencer 或暂缓部署的 Wayfinder 优化。

- 不改变作祟的敌友关系或救赎瞥视资格；合法伤害正常进入原生结算，不因修复额外扣反应。

## 0.9.9：精神伤痕

在可核实的魔族精神伤害应用前，询问受伤角色的操作者。确认后通过原始 Use 支付一次每日次数，并同步一次普通反应及 Reaction Checker 资源；拒绝则继续原伤害。抗力取自角色原有规则，仅作用于这次伤害，完成后不留下常驻抗力或开关。

只有原生抗免结果能够证明本次精神伤痕完全防止伤害，才让原魔族以原生意志对抗角色职业 DC。失败给予本来源的缓慢 1，保留其他来源更高的缓慢。一轮按施用者下次回合开始结束；先攻改变或回合记录无法核实时退回原起点的有限时长并提示核对。撤销原伤害只清理本来源的效果，不猜测退款。

原始使用卡和豁免卡沿用伤害来源的私密范围，隐私模式在投骰前传入原生检定，避免中途的幸运提示暴露结果。已开始付款、豁免或创建效果后发生不确定响应，会保留记录供核对，不自动再次扣费、重投或复制效果。

自动流程需要在线主 GM、可核实的原伤害与 Token、实际唯一遭遇、可用每日次数及反应，并通过当前原生兼容检查。合并多次攻击、无法区分的抗力贡献、未知模组版本、遭遇外或缺失来源的情况保留人工处理。这些是自动覆盖边界。原生验收覆盖普通 Strike、混合伤害、抗力不足，以及 GM／玩家公开和私密入口；其他原生来源路径不能据此视为已经完整实测。

完整测试 **1,436 项通过，零失败、零跳过**。两客户端实测包含实际 Toolbelt 伤害按钮、原 Use、每日与反应资源、原生抗免、私密豁免、独立缓慢及到期。测试配置启用 23 个相关模组；最新正式清单为 125 个，并未全部重测。详见[本版验收记录](https://github.com/takaqiao/fvttAutoTranslateTool/blob/pf2e-third-party-automation-v0.9.9/docs/fortress-automation/verification.md)。

反制表演、恐吓御敌及其他当前构筑差集按用户要求保持暂停。水长东旧构筑锯齿刃／双重打击漏 +1 仍只登记。

## 0.9.8：全场喝彩的结果、维持与反应限制

亵渎堡垒当前诗人的三环单目标**全场喝彩 Roaring Applause**接入原施法按钮和原 Toolbelt 意志豁免。一次原生付款绑定原法术卡；首个已核实结果自动建立该来源的禁反应、缓慢 1／迷魂，并保留其他来源的条件。效果按施法者实际下回合结束到期；需要鼓掌时在目标真实回合开始提示。

正常使用原生维持后，由 GM 在原法术卡确认完成或被打断。完成只延长该来源，并遵守原始十分钟上限；不重复扣法术位。原卡支持核对和结束本来源的迷魂，不会把手工移除的条件重新补回。重掷、断线重载及无法证明的修订保留人工核对状态，不自动重复施法、付款或创建效果。

已核实的禁反应会阻止本模块支持的反应入口，包括已发卡预付的盾牌格挡，以及盾挡／救赎瞥视等待期间新发生的限制。Reaction Checker 1.4.3 的准确源码与原按钮通过核验后，已有反应提示卡也会停止执行；原始资源和既有付款记录保留，效果结束后按当时真实剩余资源恢复。未核实的模组版本、外部宏和预先选择的外部修正仍需手工处理，原卡显示当前覆盖状态。

本批完整测试 1280 项通过，并验明真实玩家／GM 施法、四档豁免、条件来源、维持、到期、旧反应卡、直接／预付格挡，以及最后一次异步等待后的盾挡／救赎瞥视限制。验收包含 23 个相关启用模组，并非正式服全部 121 模组的完整重测；缺少私有图片等既有环境日志单独保留。发布与正式服安装分开，详见[本版验收记录](https://github.com/takaqiao/fvttAutoTranslateTool/blob/pf2e-third-party-automation-v0.9.8/docs/fortress-automation/verification.md)。

反制表演、精神伤痕及其余当前构筑差集继续逐项处理。水长东旧构筑锯齿刃／双重打击漏 +1 仍只登记。

## 0.9.7：力场飞弹原施法入口

当前接入1–3环招牌法术。动作数、分配总数、非负整数、目标、射程和可见性在付款前校验；关闭分配窗不扣位、不投骰、不出卡。零弹目标不生成伤害卡。保留准确原法术卡，原卡的通用伤害按钮改为指向本次分弹卡，避免再次生成未分配伤害。

分弹数和伤害构造复用已核验 Workbench 7.7.5 内部宏，按版本与完整命令校验，只调整本次调用的选择、付款和消息交付。每个目标仍使用原生 DamageRoll 与抗免结算；应用伤害沿用原按钮，不自动改目标生命值。原有独立 Workbench 宏入口未被全局替换。

本批限公开施法、当前已核验的法术条目、唯一关联施法 Token，以及支持的同高地图和可核实的目标。玩家须确认角色能看见目标；私密施法、隐藏／隐形与特殊感官、未支持的空间关系、消耗品、其他变体或额外增伤保留人工处理。这里的限制是自动覆盖范围，不是规则禁用。未新增动作池扣费或动画。

原生付款与分弹交付均绑定同一次施法。取消付款不会产生伤害；付款或消息回复不确定时保存已知记录，不自动再次扣费、退款、重投或重发。已经发出的目标伤害卡保留供 GM 核对。本批验证包含玩家／GM 双客户端正常及故障流程；不是全部121个正式模块的完整兼容重测。详细证据见[本版验收记录](https://github.com/takaqiao/fvttAutoTranslateTool/blob/pf2e-third-party-automation-v0.9.7/docs/fortress-automation/verification.md)。


已知问题：Reaction 1.4.3在有真实Shield Wall专长持有者时，原举盾回调在两版系统均出现`a is not defined`。此上游既有分支本批未修复，不计为通过；本模块的无持有者兼容分支已通过验证。

连接正常技能使用、聊天卡和PF2e Dailies。面向Foundry V14 / PF2e8.5.0及8.5.1；依赖socketlib、libWrapper、PF2e Dailies4.20+。技能自动结算需要在线主GM。实际验证和安装状态以该版本的验收、部署回执为准。

## 0.9.6：半身人幸运

在能够确认结果公开的原生技能检定或豁免失败时，询问投骰者是否使用原专长。确认后通过原始 Use 消耗每日一次，沿用同次检定的修正与 DC 原生重投，必须采用新结果，不额外加值、不消耗反应。调用方只收到最终结果；拒绝、次数耗尽或原检定取消不会启动额外使用。

本批只接入亵渎堡垒的 PF2e 8.5.1。暗骰、私密结果、已占用的幸运／厄运、替代骰、已经重投、无 DC 或无法核实的检定保留手工处理。当前 Patreon 设置会把技能检定改为暗骰，这些技能不会出现自动幸运提示。Toolbelt 把豁免保存在原卡目标行时没有向原生入口传递完整隐私信息，本版同样保留手工幸运；普通原生豁免的公开入口已有玩家／GM 双客户端验收。

同一角色兼有倒转光阴或喀咯时继续由既有流程处理，半身人幸运保留手工使用。单独使用专长不会自动寻找旧检定。付款、投骰或回调中断时保留已知记录，不自动再次扣费、投骰、退款或重放后续效果。需有在线主 GM；其它未验证的构筑或客户端组合不据此宣称覆盖。详细证据与未覆盖场景见[本版验收记录](https://github.com/takaqiao/fvttAutoTranslateTool/blob/pf2e-third-party-automation-v0.9.6/docs/fortress-automation/verification.md)。

## 0.9.5：绝境祷告、列盾突进与救赎瞥视

以下保留该版本发布时的覆盖与后续工作记录。

本版接入亵渎堡垒当前构筑的三项能力，验收基于 Foundry 14.368 / PF2e 8.5.1。新增功能使用当前 23 模块测试配置，不代表正式团全部 121 个模块都重新验收，也不表示其余能力已经补完。发布与正式世界安装分别记录。

**绝境祷告**在真实回合开始的合法机会询问玩家，通过原始 Use 支付每日次数并获得受限的临时聚能。它与后来恢复的普通聚能分开记录；当前授予的圣疗和武器涌能通过原生施法支付时优先使用该临时点。未使用的临时点到期只移除自己这一点，保留普通聚能。展示卡、错过机会后的使用或已有普通聚能时不会借用旧机会。无法证明支付或资源变更归属时保留记录，转手工处理，不自动重试或恢复旧聚能池。

**列盾突进**从原专长的真实 Use 开始，由原 Patreon 规则举盾，随后让原操作者在地图上计划并完成一次原生 Stride。移动完成后可选择触及内的敌人、现有近战 Strike 与当前 MAP，使用原生攻击流程完成内含打击。只检查自己所选武器的触及，不要求敌人能够反向触及。整项活动记录为双动作华丽；内含移动和 Strike 不再另记一个活动，重复使用不会重复移动或攻击。当前只接入角色已准备的陆地速度 20 尺；零成本或取消移动、其他移动模式，以及未核验的 AAT 配置保留手工后续。启动时修复了 Patreon 使用门禁的客户端须整页刷新后再自动继续。

**救赎瞥视**在有可核实原始来源的盟友伤害应用前，询问合资格神卫玩家是否使用反应，再由伤害来源的操作者选择分支。防止伤害分支沿用原生零伤害应用，不再损伤盟友盾牌或追加盟友格挡费用；抗力分支使用一次伤害范围内的原生抗力计算，并经已核验 Trigger Engine 路径创建该来源的衰弱 2。准确原 Use 只能与唯一正在等待的伤害合并付款，同一来源不重复结算。原有 Patreon 和 Trove 规则内容保留。

救赎瞥视自动路径要求 **PF2e 8.5.1**，当前限 5 级、未取得 Weight of Guilt 的已核验构筑，需要双方关系、神卫灵光及原伤害来源均可证明。接入可核验的主要原生攻击或豁免伤害来源；本轮浏览器伤害矩阵使用真实攻击来源，不能据此声称所有豁免伤害组合都已原生测试。持续伤害专用流程、合并多次攻击、未知来源与其它未核验组合需手工结算。来源清楚的一次攻击内多种伤害与“合并多次攻击”不同：前者已有抗力原生用例，后者不在自动范围。

依赖图停用或世界中出现当前实现不支持的持有者时，恢复原有提醒，保留其他提醒设置；兼容层只补读取结果，不改写 Reaction 的战斗缓存或反应资源。原生验收已确认恢复后真实伤害卡会重新产生旧提醒。准确敌方回合到期的机械断言也已通过，但独立复现的遭遇追踪器 UI 错误使该轮脚本未全部通过，详见[本版验收记录](https://github.com/takaqiao/fvttAutoTranslateTool/blob/pf2e-third-party-automation-v0.9.5/docs/fortress-automation/verification.md)。全场喝彩、反制表演、半身人幸运和精神伤痕等其余差集继续保留原有提供者覆盖，未在本版新增实现。已登记的旧构筑锯齿刃／双重打击问题不在本版。

本版还修正电力到期处理的空写入：只有确有受电、待结算状态或蓄电需要清理时才保存，普通角色结束战斗不会因此新增空操作记录。原生检查确认真实蓄电仍会正常清除；测试清理期间保留的第三方／画布错误详见验收记录。

## 0.9.4：连击、格挡与魔宠

- **队友增益**：灌注盟友、帝国血脉魔法、投入守护与线索共享按真实发起者和目标结算。守护检查举盾、邻接与有效期；线索共享给触发队友并处理十分钟频次；血脉效果保留其他仍在有效期内的受益者。
- **赤凰专长**：竖起盾墙、典范战地医疗、断天剑碎地拳、渴饮吾敌之血、粉碎防御和猛烈摔击接入原生检定与实际伤害结果。渴饮吾敌之血读取前一绑定打击实际造成的伤害；不会拿聊天显示的总伤害代替。灵识的30尺不精确生命感知已由原生subfeatures覆盖，不另加一份。
- **憎恶能力**：动态护盾的动作数、硬度、原生格挡与十分钟免疫；动态及普通虚能噬的真实豁免结果与短期虚弱；恢复心智的治疗/心灵豁免分支和免疫；抖擞的惊惧与有来源DC的恶心检定；熵能轮的时限、环级上限和每回合增长；心灵疗愈替代增幅的情绪意志豁免效果。
- **热流谐摆**：核对现用的11项法术来源，修补授予法术的冷热转换名单。新遭遇第一次施法选择火焰或寒冷，之后自动交替；Workbench重新聚能后恢复中性，满聚能也能处理。这些法术的聊天卡保存本次能量和增幅选择，之后切换状态不会改写旧卡的伤害及伤害特征；伤害仍由原生规则计算。
- **知识与架势**：怪物猎手、已知弱点和军师架势使用真实知识检定来源、目标、结果与知情盟友。秘密检定不公开答案或DC；攻击机会由主GM统一处理。
- **无需惊慌**：正常使用后，对实际10尺散发范围内符合听觉、语言与免疫条件的生物，以同一次交涉检定比较各自意志DC，自动降低惊惧并处理一小时免疫。
- **奥术演化**：原生Dailies每日准备中选择额外招牌法术；确有已学习法术记录时才提供临时加入分支。休息还原招牌状态、删除临时法术，不额外制造环位。

目标、当前MAP、反应是否使用和专长规定的分支仍由玩家选择；选择后的效果、资源、掷骰和联动自动执行。选择窗口发回实际操作者，不要求GM代点维护面板。攻击的正常伤害应用仍沿用系统入口，附加后果跟随该次伤害自动结算。

接管的增幅心能与帝国血脉施法会核验原生资源支付。正常施法已支付时不会再扣；直接发送法术卡作为使用时，由原生施法条目扣除一次所需资源，资源不足则不增加效果。未发送的草稿不扣费。真正施法后取消额外收益选择，不会退还已经施放法术的资源。

主GM首次进入会先保存配置备份，再窄修本模块接管的Patreon规则，避免重复加效果。有怪物猎手且启用Ranged Combat的队伍会改为完整原生行动卡，以保留猎物指定的来源信息。其他规则不整体关闭。

自动化依赖可验证的规则事实。没有恶心来源DC时不凭等级生成DC；混合物理/元素伤害无法从原生IWR回执确认元素穿透量时，不推测熵能轮增长。诅咒/疾病诊断、隐藏知识内容和必须由GM判定的场景事实不会被伪造。已经应用的额外伤害拥有原生独立撤销记录。

## 玩家正常使用

- **鼓舞之息**：直接点角色卡/HUD/Toolbelt的使用按钮、使用原生热栏，或把此技能发到聊天。自动恢复1聚能并处理每日次数；系统按钮已扣次数时不再重复扣，满聚能会返还本次按钮扣除的次数。
- **昼夜规律师**：休息规定时间后使用技能或发技能卡。自动按等级标准DC掷生存，并处理治疗、疲乏、流失。不会恢复法术/每日次数；世界时间记录阻止24小时内重复获得休息效果。GM记录中已超过1日未整夜休息时自动失败。
- **魔法物品传奇、能量调谐**：在原生Dailies每日准备窗口选择物品和元素，点击准备即可。传奇最多两件非消耗品魔法物品；可变内联启动DC成为职业/法术DC较高值减2。剑气波力场/精魂伤害随调谐转换，法术区保留正常转换开关。
- **循环能量**：在伤害应用之前正常使用此反应；可以从原伤害卡点击“循环能量”，也可以使用自己的技能卡。自动关联以该角色为目标且具有调谐特征的伤害。应用伤害时，等级抗力自动进入原生IWR，与原有抗力、弱点、盾牌和临时生命值共同计算；之后自动创建打击加伤并跟踪下个本人回合结束。无需手填抗力或添加效果。

技能原聊天卡显示自动处理结果。没有额外玩家操作面板。玩家仍决定是否使用反应，以及每日选择；若一个触发效果同时符合命能和虚能，选择要循环的特征是该能力本身的规则选择。

## 自动数据补缺

主GM进入世界后，自动核查活动队伍并备份修复已确认的原始缺口：圣天龙息巨剑公式、动态虚能噬两动作伤害、热流谐摆已识别的伤害转换名单，以及已有唯一明确修炼者聚能栏中的遗漏剑气波。活动队伍成员变动或新增条目也会核查。不会依据名称猜测，不覆盖已自定义的未知字段。

不需要玩家点击修复。GM角色卡上的“第三方维护”保留检查、回滚和排错功能；手动回滚会为该角色关闭后续自动修复，避免下次又改回去。

## 边界

- 循环能量的触发是“将受到伤害”，需要在原伤害应用前使用。已经结算的旧伤害不自动补血；若操作顺序错了，使用原生撤销伤害后再反应。反应需角色参加已掷先攻的遭遇；普通技能使用自动查找最近2分钟的匹配伤害，原伤害卡按钮能精确指定来源。
- 抗力只在本次原生伤害调用中存在，不留下永久抗力；后续加伤使用独立原生效果。
- 物品传奇处理固定数值的可变`@Check` DC，不修改immutable检定或普通文本数字。调谐只转换已核对源UUID的剑气波，不把所有天夏包法术当作修炼者法术。
- 休息记录使用Foundry世界时间；不会擅自推进整个世界的时间。首次使用前未被记录的历史整夜休息无法重建，使用技能视为玩家按规则进行该休息。之后会记录原生整夜休息与本能力结算。
- 没有在线GM、频次回执超时或操作中断时明确报错，不重复执行恢复或追溯修正伤害。不同GM账号的请求统一交给主GM；同一GM账号多窗口同时在线未列入已验证场景。
- 热流谐摆快照覆盖本轮核实的11个法术来源。现役穆勒没有mindshift条目；其他mindshift动作沿用既有Patreon处理，新构筑的守恒联动需另外核验。

正常完整休息由PF2e执行；Dailies负责清理每日临时效果并保留上次选择，下一日直接在原生窗口重新准备。

## 安装与开发

本版支持目标为精确已知的PF2e8.5.0/8.5.1字节；桥证明只覆盖客户端本次加载时下载的完整系统源码、保留的原生applyDamage函数及当前bridge身份，不能证明之后仅在磁盘替换的文件或整个已加载的私有闭包。正式安装与后续官方系统更新均须按协调流程停服写入、受管服务重启，再刷新客户端取得新证明；单独刷新世界或在同一进程Setup更新后Launch World不重建桥。未知字节或缺桥只报告对应能力不可用，不能靠修改verified元数据恢复兼容。


将zip内的`pf2e-third-party-automation`目录放入Data/modules，启用本模块及依赖。升级后需重新进入世界，加载新增的正常使用入口与配置修复。

源仓库测试：`node --test tests/*.test.mjs`。真实QA验证正常聊天、纯原生Use、热栏、Toolbelt、HUD动作侧栏、Dailies提交、部分/完整休息、原生IWR与伤害撤销。测试角色、私有依赖和第三方付费正文不进入发布包。

GM维护宏（正常游戏无需使用）：

```js
game.modules.get('pf2e-third-party-automation').api.open();
```

GM维护入口负责0.2的字段修复及其回滚；0.3的配置备份保存在世界设置configurationBackups，效果按本模块来源标记识别。完整停用时需还原相应Patreon配置并清理仍有效的本模块效果，不能只卸载文件。新补入的剑气波法术按需手动删除。已经完成的恢复和检定不会因停用而倒退。
